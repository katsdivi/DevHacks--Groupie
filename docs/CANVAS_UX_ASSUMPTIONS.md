### From INSTANT

## INSTANT

- **Intent parsing** (`canvas/instant.ts`, no model): "week", "this week", "7 days", "soon" mean the next 7 days; "next", "soonest", "upcoming" mean the single next dated item; anything left after dropping filler words ("send me my", "what's", "assignment", "details", ...) is a named search; a bare "due" with nothing else means the week; empty text keeps today's code flow. Named search needs every query word in the title (word prefix for words of 3+ letters, numbers exact, so "sprint 3" never matches "Sprint 13").
- **Data read**: only the verified `ctx.from.id`. Live `calendar_events` due from now on, plus `cubbie_imports` the user made (personal or for a group) and imports for groups the user has a member row in (the group's assignment, which every member already sees). Failed imports and past-due imports are skipped; imports with no due date only show up in named searches. An import also saved to the calendar (`cubbie-import-<id>`, or same title and due time) shows once, with the import's points and description. Calendar feed descriptions are used when there is no import.
- **"Course names only" in a group with no `canvas_course`**: read conservatively. Nothing personal is posted in that group: the group gets "Sent you the details in DM." and the list goes by DM. With a course set, only items in that course (matched by `sameCourse`) and the group's own imports are posted in the group; the rest goes by DM in the same reply turn. DM failures use the qa.ts pattern (`markCannotDm`, `DM_BLOCKED` in the group).
- **Buttons go on the top item only** (the next item, the first match, or the soonest in a week list) so a list does not get a row of buttons per item. Lists show up to 6 items, then "And N more in Upcoming."
- **[Pull full details via Cubbie] is always personal**: an unlinked user gets a fresh personal pair code in the prefilled text (`Groupie import <CODE> <title>`), so pulling details never replaces a group's assignment. A linked user gets `Groupie import <title>` with no code, relying on LINKED's code-free personal imports. Titles are clipped to 120 characters for the prefilled text.
- **[Split this one]** shows only when the group is still waiting for its assignment. Callback data is `cv:split:e<calendar id>` or `cv:split:i<import id>`. Only the person who asked can use it (the item is re-read through the owner-only helper with the tapper's id and must still be in the group's scope); a teammate gets an alert "Only the person who asked can split this one." It always issues a group code for the tapper.
- **A named assignment not found in a group waiting for its assignment** falls back to today's code flow with the words as the hint, since "/canvas Project 2" there has always meant "import it". In a DM, or in a group that already has its assignment, it says it could not find it and offers the Pull button.
- **Nothing connected** means no live calendar rows at all (past or future) and no imports. [Connect calendar] opens the group's calendar screen, or the user's first joined or pending group from a DM, or `https://t.me/<bot>/<short name>` with no `startapp` when there is no group (not verified that the Mini App opens a sensible screen without a group). The Cubbie button there uses a group code when the group is waiting for its assignment, else the Pull rules above.
- **Install line**: hidden when the user has a non-revoked `cubbie_links` row (`isLinked` in `membership.ts`), in the instant answers and in the plain `/canvas` code replies (steps renumbered). The plain code replies also gained an [Open in iMessage] button (prefilled with the exact message).
- **Wrong app**: every Cubbie-bound text now gets "That one's for Cubbie in iMessage." (replacing "That one goes to Cubbie in iMessage, not here" in the reply), the exact text in a code block, [Open in iMessage] and [Copy]. A 6-character first word counts as a code only if it uses the code alphabet and has a digit, was typed in capitals, or exists as a pair code, so "groupie import sprint 3" and "report" are words. Code-free imports: linked users in a DM keep the text code-free; everyone else gets a code (group code in a group, as before). "Groupie status" is never given a code; unlinked users get "Link your iMessage first: send me /imessage here." (or "DM me /imessage." in a group). Two assertions in `bot/routing.test.ts` were switched from `copy.WRONG_APP` to `copy.WRONG_APP_CUBBIE`.
- **Membership**: `projectGroupsFor(userId)` = groups with a member row (joined), then groups where the user made an import pair code or an import but has no member row (pending), newest first. Link codes do not count. Telegram chat membership itself is not stored anywhere, so a member of the chat who never made a code or import is still unknown.
- **meView**: pending groups are included in `groups` (group facts every member sees, `myTasks: []`) and the sentence "You're in <group> but haven't added your details yet." is appended to `summary`, since `CubbieMeResponse` has no pending flag and `packages/shared` is off limits. A real flag needs a shared schema change and `status.py`.
- **DM path**: when the user has no joined group but a pending one, DMs mentioning tasks, group, project, team, split, status, my part, progress, meeting or assignment get the fixed line plus [Add my details] (`appUrl(groupId, 'form')`) with no model call. Other DMs still go to the model, whose prompt now says they are in that group without details (never "not in any project group"), and the reply carries the [Add my details] button.

### From LINKED

## LINKED

Logged by the LINKED agent (branch `feat/canvas-ux-linked`).

1. **Route mount.** `POST /api/cubbie/import/linked` is a second route on `cubbieImportRouter`. The existing `app.use('/api/cubbie/import', ...)` raw-body parser (15 MB) and `cubbieImportErrors` are prefix mounts, so they already cover `/linked`; no new parser line. `index.ts` gains two mounts: `skillVersionTap` on `/api/cubbie` (before the import and link routers; never blocks) and `GET /go/cubbie` (before the SPA fallback, whose regex would otherwise serve `index.html` for `/go/*`).
2. **Shared core.** `runImport` in `importer.ts` now ends by calling the exported `runImportCore({ telegramUserId, group, code, lockKey, payload, requestId, opts })`, which is the old tail unchanged (insert, prepare, personal or group intake, files, mark used on success). The code path's checks and messages are identical and its tests pass untouched. `IMPORT_ERROR_STATUS` is unchanged; the linked list is `LINKED_ERROR_STATUS = { ...IMPORT_ERROR_STATUS, bad_link: 401, choose_target: 409 }` in `linkedImport.ts`.
3. **Check order (linked).** imports off, no body, signature (`bad_signature`), bearer token (`bad_link`), JSON and schema (`invalid_payload`), per-IP then per-student rate limits (same `ip:` and `user:` keys as the code path, so both paths share the hourly budget), then target. The token is checked before the body is parsed, so a bad link never reveals schema details. A user id in the body is never read.
4. **Context code.** "Recent code" means the student's import-purpose codes that are unused, unexpired and made in the last 30 minutes. A used code is not context (it would only re-fail). Group and DM codes are distinct places; one place means use it, zero or two or more means `choose_target`. A recent code whose group row is gone also asks. With an explicit `target`, the newest recent unused code for that same place (group id, or DM for `me`) is still attached as context, so the Mini App's poll on that code shows the import, and it is marked used on success. With no such code the import row has `pair_code` null.
5. **Ownership.** An explicit group target needs a `members` row for the student in that group or any import code the student made for it (any age). No Telegram `getChatMember` call: it is slow, and the codes already cover students who are in the chat but have not added details. Unknown groups and groups the student is not tied to both answer `400 invalid_payload` with "That is not one of your Groupie groups. Pick one from the list, or Just me." (not `bad_link`, as the brief says).
6. **choose_target options.** Groups from member rows and import codes, newest activity first (member `created_at` or code `created_at`), only groups that still exist, max 5, then `{ kind: 'me', title: 'Just me' }`. Group title is `groups.title` (fallback "Your group").
7. **In-flight lock (linked).** Locks on the context code when there is one (so a code import and a linked import using the same code exclude each other), else on `linked:<user>:<groupId|me>`. Its `code_used` message is "This assignment is being imported right now. Check your group in a moment."
8. **Failure messages.** Linked imports reuse the core's failure messages, some of which say "Your code still works". The Skill maps `server_error` to its own "hit a snag" line anyway, so students do not see the server text; left as is to keep the core identical.
9. **`linked` and `skillOutdated`.** `linked` comes from a new `isLinked(userId)` appended to `link.ts` (plus `touchLink`, for `last_used_at`). There is no column for the Skill version and `link.ts` handlers are not mine, so the version is best effort and in memory: `skillVersionTap` notes `groupie-import-skill/N` for any `/api/cubbie/*` request with a live bearer token (covers `/me`, `DELETE /link`, `/import/linked`), and a successful code import notes it via its `importId`. `skillOutdated: true` is sent only when a version below 3 was seen since the last restart; otherwise the field is omitted. `linked` is optional in the shared schemas (the Mini App builds local status objects without it); the server always sends it.
10. **Mini App install step.** The last `linked`/`skillOutdated` answer is cached in `localStorage` (`groupie.cubbieLinkState`) because the install step shows before any code exists. Before a code: shown unless the cache says linked and current. After a code: shown in the waiting panel when the server says not linked or outdated (never both at once, the pre-code panel disappears when a code exists). An outdated Skill gets "Update the skill" copy and no "Done" toggle. Linked students also see "the code is optional: Groupie import Project 2 works too."
11. **Open in iMessage (web).** `CopyRow` takes `open` and then shows [Open in iMessage] and [Copy] side by side under the text. It opens `${location.origin}${goCubbiePath(text)}` with Telegram `openLink` (or a new tab outside Telegram). `goCubbiePath` is a new shared helper; `cubbieOpenUrl` in `goCubbie.ts` is unchanged (same path, server side with `PUBLIC_URL`). Used for the code message and the install message.
12. **/go/cubbie.** The sms form is `sms:<handle>&body=<encodeURIComponent(text)>` (the iOS 8+ form; iMessage is iOS only). A phone number typed with spaces, dashes or brackets is compacted to + and digits; the handle is then used only if it matches `[+0-9A-Za-z@._-]{3,100}`, else treated as unset with one warning log. Text is capped to 500 code points before escaping. Auto-redirect only on iPhone, iPad, iPod or Android user agents, 400 ms after load, and only when the sms link exists. No CSP or framing header is added; nothing else in the app sets one either. `CUBBIE_HANDLE` is one line in `env.ts`, default empty.
13. **Skill v3.** `send.py` decides by the file: a `pairCode` (or `--code`) always takes the code path, unchanged, even when linked; a bad code is still the bad-code line. Only with no code at all does it read `~/.config/groupie/token` (now defined in `send.py`; `groupie_link.token_path` delegates to it, so `link.py` and `status.py` share the file) and post to `/import/linked` with the bearer. No code and no token prints "I need the code from Groupie for this one..." with exit 3 and sends nothing. New exits: 14 `choose_target` (stdout "Which group? 1. A 2. B 3. Just me"; stderr notes `target N: <groupId|me> (<title>)`; the options are saved to `~/.config/groupie/targets.json`, mode 600, ids and titles only) and 15 `bad_link` (stdout "Your Groupie link expired. Send /imessage in Groupie to relink."; deletes the saved token, like `status.py` does on 401). `--target` takes `me`, a list number (from `targets.json`), or a group id (any number with absolute value over 100). A target that fits nothing prints "That isn't one of the choices. Text me the number from the list." with exit 14 and sends nothing. The user agent is `groupie-import-skill/3` (defined once in `send.py`; `link.py` and `status.py` use it). The token format is unchanged (`grp_` plus 32 random bytes base64url).
